Unsupervised

  • Input: \(X\) only
  • “What structure is in here?”
  • Output: components, clusters, neighbours
  • Judged by: interpretability, usefulness

Supervised

  • Input: \(X\) and \(y\)
  • “Given \(X\), what is \(y\)?”
  • Output: a prediction for a new row
  • Judged by: error on rows the model has not seen
  • There is a right answer, and we can check against it

Supervised learning: the vocabulary

Types of Machine Learning

  1. Unsupervised: unlabelled data, find structure (sessions 06–08)
  2. Supervised: labelled data, predict outcomes (today)
  3. Self-supervised: create labels from the data itself (how LLMs are pre-trained)
  4. Reinforcement: learn through reward from interacting with an environment

Key Concepts

  1. 🏋️‍♂️ Training data: rows where we know \(y\)
  2. 🏷️ Features and labels: \(X\) and \(y\)
  3. 🧠 Model: a family of functions to choose from
  4. 📉 Loss: how wrong a prediction is, as one number
  5. 📊 Evaluation: loss or metric on rows the model has not seen
  6. 🌐 Generalisation: doing well on the next city, not the last one

Mathematical Representation

  • Features: \(X = (x_1, x_2, \dots, x_p)\), e.g. internet speed, safety, freedom score
  • Target: \(y\), e.g. monthly cost
  • Model: \(f(X; \theta)\), e.g. \(f(X) = w_0 + w_1 x_1 + \dots + w_p x_p\)
  • Parameters: \(\theta\), the values learned in training (here the weights \(w\))

We look for \(\theta\) such that

\[y \approx f(X; \theta)\]

for cities the model has not seen.

Fitting means choosing theta. “Close” needs a definition: that is the loss.

Loss Functions

Mean Squared Error (Regression)

\[MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2\]

The average squared distance between prediction and truth. Squaring punishes big misses much more than small ones. A city predicted 2,000 USD off costs 100× more than one predicted 200 off.

Cross-Entropy (Classification)

\[H(p,q) = -\sum_{k}p_k\log q_k\]

Compares the true label \(p\) (1 for the right class, 0 otherwise) with the predicted probabilities \(q\). It only looks at the probability given to the right class, and punishes confident wrong answers hardest: \(-\log(0.01) \approx 4.6\).

Loss Functions in Code I

Mean Squared Error

import numpy as np

y     = np.array([3.5, 2.1, 4.0, 5.5, 6.1, 7.3, 3.9, 4.4, 5.0, 6.7])
y_hat = np.array([3.8, 2.0, 4.2, 5.0, 6.0, 7.5, 3.5, 4.2, 5.1, 6.8])

mse = np.mean((y - y_hat) ** 2)   # 0.066

\[MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2\]

In practice we often report RMSE \(= \sqrt{MSE}\) or MAE, because they are in the units of \(y\) (USD, not USD²).

Cross-Validation

  • Split into \(k\) folds; train on \(k-1\), test on the one left out; rotate
  • Gives \(k\) scores instead of one: an average and a spread
  • A more stable estimate of performance. It does not by itself reduce overfitting.
from sklearn.model_selection import cross_val_score

                         scoring="neg_mean_absolute_error")

Bias-Variance Tradeoff

  • Bias: error from a model too simple to capture the pattern (underfitting). Depth-3 tree.
  • Variance: error from a model so flexible it fits the noise (overfitting). Unlimited tree, 1-NN.
  • Irreducible error: noise no model can explain

Goal: the complexity where test error is lowest.

Bias-Variance Tradeoff

Mathematical Representation of Bias-Variance

For a given point \(x\), the expected prediction error is:

\[E[(y - \hat{f}(x))^2] = \text{Var}(\hat{f}(x)) + [\text{Bias}(\hat{f}(x))]^2 + \text{Var}(\epsilon)\]

  • \(\text{Var}(\hat{f}(x))\): how much the prediction would change with a different training sample
  • \([\text{Bias}(\hat{f}(x))]^2\): how far the average prediction is from the truth
  • \(\text{Var}(\epsilon)\): the irreducible error

Imagine drawing many training sets and fitting the model each time. Variance: how much the predictions for Aalborg jump around. Bias: how far their average sits from the true value.

Regularization: Preventing Overfitting

  • Overfitting: the model fits the training rows too closely and does worse on new ones
  • Regularization: add a penalty on large coefficients, trading a little bias for less variance

Common Regularization Methods

  • Lasso (L1): pushes some coefficients to exactly zero, so it also selects features
  • Ridge (L2): shrinks all coefficients, keeps all features
  • Elastic Net: a mix of both

Elastic Net penalty

\[\lambda \sum_{j=1}^{p} \left[ \alpha |\beta_j| + \tfrac{1-\alpha}{2} \beta_j^2 \right]\]

  • \(\lambda\): overall strength (alpha in scikit-learn)
  • \(\alpha\): mix between L1 and L2 (l1_ratio in scikit-learn); \(\alpha = 1\) is Lasso, \(\alpha = 0\) is Ridge

Leakage: what will you know at prediction time?

With all columns, linear regression reaches test \(R^2 = 0.74\). Without four of them, \(0.37\).

The four: cost_expat, cost_coworking, coffee_in_cafe, cost_beer.

  • If nobody has reported the cost of living yet, will you have the price of a coworking desk?
  • A feature is only legitimate if it exists when the prediction is made
  • Leakage makes models look excellent in the notebook and fail in use

Also: coffee_in_cafe and cost_beer are identical in all 780 rows, and Samara has a racism score of \(1.8 \times 10^{28}\) on a 0–1 scale. EDA from session 03 still applies.

Popular Model Classes

Linear Models

  1. Linear regression \[y = \beta_0 + \beta_1x_1 + \beta_2x_2 + \dots + \beta_px_p + \epsilon\]

  2. Logistic regression (binary classification) \[P(y=1 \mid X) = \frac{1}{1 + e^{-(\beta_0 + \beta_1x_1 + \dots + \beta_px_p)}}\]

  3. Regularised versions: Ridge, Lasso, Elastic Net

Fast, stable, and each coefficient can be read directly. They miss interactions and curves unless you build them in.

Neighbour Models

k-nearest neighbours: predict from the \(k\) most similar training rows.

  • Regression: average their \(y\). Classification: majority vote.
  • No training beyond storing the data
  • Small \(k\) gives high variance (1-NN memorises); large \(k\) gives high bias
  • Needs scaling, because it is built on distances (as in session 08)

Tree-based Models

  1. Decision trees
    • Recursive binary splits on one feature at a time
    • Split quality: Gini impurity, entropy (classification); squared error (regression)
  2. Random forests
    • Many deep trees on bootstrap samples and random feature subsets, averaged
    • Averaging cancels much of the variance
  3. Gradient boosting (e.g. XGBoost)
    • Shallow trees added one after another, each fixing the errors of the last
    • Session 10

Decision Trees

A real depth-2 tree on all 780 cities. A lower press freedom index means a freer press.

Neural Networks

  1. Multi-layer perceptron: layers of weighted sums and non-linear activations (ReLU, sigmoid)
  2. Recurrent networks, LSTMs: sequences
  3. Transformers: attention over long contexts; language models, and increasingly tables, images and time series
  4. Graph neural networks: data shaped as networks

On tabular business data like ours, tree ensembles are usually the stronger baseline. Module 4 goes deep on these.

Interpretation

What drives the prediction?

  • Coefficients (linear models): the change in \(y\) per unit of \(x\), holding the other features fixed. Standardise first to compare them.
  • Feature importance (trees): how much each feature reduced the loss across all splits
  • SHAP values: for one prediction, how much each feature pushed it up or down from the average

All three describe the model, not the world. A feature that predicts cost does not cause cost.

Prediction versus causation is one of the module’s learning objectives, and a likely exam question.

Practical Considerations

Feature Engineering

  • Creating relevant features: ratios, dates split into parts, group averages
  • Handling missing data: fill or drop, and decide it on the training data only
  • Scaling: for anything built on distances or penalties (kNN, SVM, regularised models)
  • Categorical variables: one-hot encoding, e.g. region
from sklearn.preprocessing import OneHotEncoder

encoder = OneHotEncoder(sparse_output=False, handle_unknown="ignore")
X_region = encoder.fit_transform(df[["region"]])

Pipelines: preprocessing belongs inside

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsRegressor

model = make_pipeline(StandardScaler(), KNeighborsRegressor(n_neighbors=5))
model.fit(X_train, y_train)
model.predict(X_test)

The scaler learns its means and standard deviations from the training rows only. Scaling the full table first leaks the test set into training.

Model Selection and Tuning

  • Hyperparameters: settings you choose, not learned: \(k\) in kNN, tree depth, \(\lambda\)
  • Choose them with cross-validation on the training set; touch the test set once, at the end
  • Grid search or random search
from sklearn.model_selection import GridSearchCV

param_grid = {"kneighborsregressor__n_neighbors": [1, 3, 5, 10, 20]}
search = GridSearchCV(model, param_grid, cv=5,
                      scoring="neg_mean_absolute_error")
search.fit(X_train, y_train)

Conclusion

Key Takeaways

  • Unsupervised learning asks what structure is in \(X\). Supervised learning asks what \(y\) is, given \(X\).
  • The difference is the answer key, and that is what lets you measure error
  • Beat a baseline, measure on unseen data, and check for leakage
  • Balance bias and variance; regularisation and ensembles help
  • Pick metrics for the decision: accuracy is rarely enough
  • Interpretation describes the model, not causation
